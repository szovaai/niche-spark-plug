
## Business HQ (MVP 3.0)
- business_projects is the "business workspace"; don't add a parallel workspaces table (spec says avoid duplicating tables).
- Next-best-action and stage rules live in src/lib/businessHQ.ts with tests in businessHQ.test.ts (run `bunx vitest run`); vitest pinned to v2 because vite is v5.
- HQ metrics show only real data; unconnected sources render empty states, never fabricated numbers (spec rule).
- v_credit_balance is keyed on auth.uid(), never auth.users (authenticated can't read auth.users; it 403'd).
- _shared/tieredAI.ts normalizes role→tier and complexity aliases; redeploy every function importing it after edits.
- Pro-only edge functions call requirePro() from _shared/entitlement.ts right after validateAuth; client-side isPro checks are UI only.
- AI chat functions accept only user/assistant roles from the client; system prompts are built server-side.
- Departments are defined once in src/lib/departments.ts and rendered by pages/departments/DepartmentHub; they link to existing /tools/* routes instead of rewriting them (spec: reuse, keep legacy routes).
- External apps (ClickAdMedia, GitPage, TRAFFIQ, XAVRO, payments) are listed in src/lib/integrations.ts; status changes to connected only with a real API connection (spec: no fake integrations).
- Copy functions resolve sales intelligence through _shared/salesContext.ts with caller-scoped RLS and explicit owner filters; explicit business IDs never fall back, while ID-less legacy calls use the latest-updated owned business to match useActiveProject.
- Copy context contains whitelisted blueprint/profile facts as user-message data and shared system-level truth rules; this keeps messaging consistent without trusting embedded instructions or inventing proof.
- Funnel and marketing cache keys hash the authenticated owner, full request and resolved profile; return cached.response so business-specific copy cannot leak across tenants or remain stale after profile changes.
- Mission credit mutations use service-only RPCs through creditTasksForUser after caller authentication; canonical prices, user-scoped locks and idempotent finalization prevent client tampering and double charges.
- Product Studio stores manuscripts in product_manuscripts using optimistic revisions; nova_tasks retains generated section HTML for recovery, and PDF export uses the existing sanitized guide generator.
- Multi-format product assets live in the same manuscript JSON with validated per-format imports from the existing micro-product generator; this reuses owner/reviewer access and revision checks without duplicating storage or AI endpoints.
- Export product assets only from saved content; trackers neutralize spreadsheet formulas and bundles contain editable source plus printable assets so customer downloads cannot execute generated text.
- Team collaboration uses business_members on existing business_projects, with expiring email-matched invitations and read-only reviewers; private chats, credits, copy generation and edits remain owner-only.
- Funnel downsells use authorized business offer data with their own optional checkout link; absent offers are omitted instead of generating fictional Lite products or discounts.
- Digital fulfillment uses immutable private package files and service-only order mutations; verified customer email and live entitlement are checked before each short-lived signed download, while manual grants are complimentary, never paid orders.
